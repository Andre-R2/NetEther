# OSPF Multi-Area

OSPF supports dividing an autonomous system into multiple areas. This design reduces the size of the link-state database, limits the scope of LSA flooding, and reduces the amount of SPF computation required by routers.

## Why OSPF Uses Multiple Areas

In a single-area OSPF design, every router within the area maintains a Link-State Database describing the topology of the entire area.

As the network grows, the number of routers, links, and networks increases. This means that topology changes can generate more LSA flooding and require more SPF calculations.

Multi-area OSPF addresses this problem by dividing the OSPF domain into separate areas. Each area maintains detailed information about its own topology, while reachability between areas is exchanged through Area Border Routers.

```text
Area 1 ─── Area 0 ─── Area 2
```

The main idea is that routers do not need detailed knowledge of the internal topology of every area in the OSPF domain.

## Area 0

Area 0, also called the backbone area, provides the logical backbone for inter-area communication.

A standard multi-area design connects other areas to Area 0.

Area 0 is therefore not simply another OSPF area. It provides the path through which different areas exchange routing information.

## Area Border Router

An Area Border Router (ABR) is an OSPF router that has interfaces belonging to more than one area.

For example:

```text
Area 1
   |
  ABR
   |
Area 0
```

An ABR maintains separate LSDBs for the areas to which it belongs.

For an ABR connecting Area 0 and Area 1:

```text
Area 0 LSDB
+
Area 1 LSDB
```

The detailed topology information from Area 1 is not flooded into Area 0 as Type 1 or Type 2 LSAs.

Instead, the ABR generates inter-area advertisements that allow routers in Area 0 to reach networks located in Area 1.

## LSA Flooding Between Areas

OSPF LSAs have a defined flooding scope.

Type 1 Router LSAs and Type 2 Network LSAs are limited to their originating area.

For example, if a router in Area 1 originates a Type 1 LSA, that LSA is flooded within Area 1 but does not continue into Area 0 as the same Type 1 LSA.

This separation prevents the detailed topology of one area from being propagated throughout the entire OSPF domain.

## Type 3 Summary LSA

The Type 3 Summary LSA is used by an ABR to advertise network reachability between OSPF areas.

Despite its name, a Type 3 Summary LSA does not necessarily mean that multiple networks have been summarized into one larger prefix. It is fundamentally an inter-area reachability advertisement.

Route summarization is an additional capability that can be configured on an ABR when the addressing scheme allows it.

## Inter-Area Communication

Suppose a router in Area 0 needs to reach a network located in Area 1.

The router in Area 0 learns the network through a Type 3 LSA generated by the ABR.

The forwarding path is then:

```text
Area 0 Router → ABR → Area 1 → Destination Network
```

The ABR is responsible for forwarding traffic between the areas because its interfaces belong to both areas.

The important distinction is that the ABR does not simply advertise reachability. It is also the Layer 3 device that connects the two areas.

## SPF in Multi-Area OSPF

One of the main advantages of multi-area OSPF is that routers do not need to run SPF against the detailed topology of every area.

A router normally runs SPF using the detailed LSDB of its own area.

For destinations within the local area:

```text
Local LSDB → SPF → Best Path
```

For destinations in another area, the router uses inter-area reachability information learned through Type 3 LSAs.

This limits the impact of topology changes.

For example, if a link changes inside Area 1, the detailed Type 1 or Type 2 LSA describing that change remains within Area 1. Routers in Area 0 do not need the complete internal topology change.

The ABR maintains the information required to advertise reachability between the areas.

## Benefits of Multi-Area OSPF

Multi-area OSPF provides three main scalability benefits.

### Smaller LSDB

Routers maintain detailed topology information for their own area instead of the entire OSPF domain.

### Reduced LSA Flooding

Type 1 and Type 2 LSAs remain within their originating area instead of being flooded throughout the entire OSPF domain.

### Reduced SPF Computation

Routers do not need to run SPF against the detailed topology of every area.

These characteristics make OSPF more scalable as the network grows.

## Backbone Connectivity

For standard OSPF operation, non-backbone areas should have a logical connection to Area 0.

A typical design is:

```text
Area 1 ─── Area 0 ─── Area 2
```

Inter-area communication normally follows the backbone:

```text
Area 1 → Area 0 → Area 2
```

OSPF supports mechanisms such as virtual links for specific situations where an area cannot initially maintain the required connection to Area 0. However, virtual links are generally considered a special-case solution rather than the preferred design.
